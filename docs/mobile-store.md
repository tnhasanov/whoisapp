# Phone app: distribution, store listing and privacy answers

Drafts for the owner to review. Nothing has been submitted or published.

## Choosing how to distribute

PersonBrief is a private, single-owner workspace with closed registration.
For personal use, a public store listing is not needed:

- **iPhone:** TestFlight with *internal testers* (people on your App Store
  Connect team, up to 100). Internal builds are not reviewed by Apple and stay
  installable for 90 days per build. Alternatively, ad hoc preview builds for
  registered iPhones (`eas build -p ios --profile preview`).
- **Android:** install the preview APK directly, or use Play Console's
  *internal testing* track (up to 100 testers, no public listing).

A public listing in the App Store or Google Play is a separate decision for
the owner. Apple may question an app that only its operator can sign in to;
the fictional demo (below) is what reviewers would use.

## Privacy answers (draft)

**Privacy policy URL:** `https://<your server>/privacy` (public; set
`SUPPORT_EMAIL` on the server so it shows a contact). **Support URL:**
`https://<your server>/privacy#contact`.

### App Store — App Privacy

- **Tracking:** No. No advertising, analytics or crash-reporting SDKs.
- **Data linked to the user, used for App Functionality only:**
  - Contact Info → Name, Email Address (the account).
  - Search History (research queries).
  - User Content → Other User Content (saved briefs, private notes, tags,
    issue reports; briefs contain professional information about the people
    researched).
- **Not collected:** location, contacts (address book), health, financial
  information, browsing history, purchases, diagnostics, usage data.
- Push tokens are used only to deliver the owner's own research notices.

### Google Play — Data safety

- **Collected:** Personal info → Name, Email address (account management,
  app functionality); App activity → In-app search history, Other
  user-generated content (app functionality); Device or other IDs → push token
  (app functionality, only when notifications are turned on).
- **Shared with third parties:** No (hosting and push delivery are service
  providers acting for the operator).
- **Encrypted in transit:** Yes (release builds only connect over HTTPS).
- **Deletion:** briefs and notes can be deleted in the app. Accounts are
  created by the operator, not in the app, so the in-app account-deletion
  requirement for apps that let users sign up does not apply; deletion
  requests go to the operator (see `/privacy`).

## Review notes (if submitting for review)

- Turn on the fictional demo on the server for the review period
  (`PUBLIC_DEMO_ENABLED=true`): the welcome screen then shows "Open the
  fictional demo", which needs no account and contains only invented people
  and sources. Turn it off again afterwards if you do not want visitors.
- Do not hand reviewers the owner's password.
- Mention: closed registration (accounts created by the operator), no
  in-app purchases, notifications are opt-in and generic, Face ID is used
  only for the optional app lock, and the app opens public source pages in
  the system browser sheet. That browser access counts as unrestricted web
  access in the age-rating questionnaire, which raises the minimum age
  rating; answer the questionnaires accordingly.
- Encryption: standard HTTPS only (`usesNonExemptEncryption: false`).
